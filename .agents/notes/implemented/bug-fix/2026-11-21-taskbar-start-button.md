# Agent Note: 任务栏插件避让 Windows 开始按钮

Status: implemented

## Problem

嵌入主任务栏的玄枢窗口按插件总宽度占位。Windows 11 居中布局下，插件增宽或应用按钮增多，都可能让玄枢的右端进入开始按钮。即使该处没有绘制内容，子窗口仍然拦截点击。

在 Windows 11 26200 的一次现场测量中，玄枢占用物理像素区间 `[0, 1418)`，UI Automation 报告开始按钮为 `[1359, 1449)`。对按钮中心做 `WindowFromPoint` 命中测试，返回的是玄枢子窗口。

## Decision

`TaskbarEmbed` 每次布局读取 `Shell_TrayWnd` 下 `Start` 子窗口的矩形。这个兼容窗口即使标为隐藏，也可能对应正在显示的开始按钮。实测它的左右边界与可点击区域各相差 1 个物理像素，因此按物理坐标在两侧多留 1 像素。

默认只使用开始按钮左侧的空间。插件总宽度超过这段空间时，原生窗口止于保护边界，各插件保留自己的槽位宽度，共用视口横向滚动。主题沿用相同的滚轮和触控板交互。用户显式将水平偏移设到按钮右侧时，宿主保留该起点。无可用宽度或暂时拿不到有效按钮矩形时收起子窗口，任务栏轮询继续寻找可用边界。

## Alternatives considered

仅在 QML 里裁剪插件能避免视觉重叠，但开始按钮中心的命中测试落到整个玄枢 HWND 上，因此必须限制原生子窗口的宽度。

从任务列表和通知区域的兼容 HWND 自动推算右侧空隙，可以在左对齐布局下利用剩余空间。同一次测量中，`MSTaskSwWClass` 的右边界为 1624，最后一个实际应用按钮延伸到 1713；按兼容矩形选址会遮住该按钮。

UI Automation 能识别实际的 `StartButton` 和应用按钮，适合独立验证点击边界。把跨进程控件树查询放进 GUI 线程的几何刷新，会让布局等待 Explorer 的辅助功能提供程序。

## Consequences

插件可滚动访问，开始按钮保留自己的点击区域。在左对齐或系统外壳未提供有效 `Start` 边界时，默认位置可能没有展示空间。手动指定右侧位置时，应用图标和通知区域的留白由使用者选择。

实机验证应分别覆盖左对齐、居中、真实 DPI 切换与 Explorer 重启，确认开始按钮能打开菜单，也能在可见插件栏滚动至末项。旧版现场命中结果只能用于确认故障。
