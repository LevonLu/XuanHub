# Agent Note: 插件弹窗使用原生状态栏所在屏幕

Status: implemented

## Problem

双屏且缩放比例不同的会话中，状态栏嵌在主任务栏，多个插件弹窗却落到左侧副屏。
旧 `BarWindow::setupBar()` 在布局之前读取 `QWindow::screen()`，只在空指针时退回主屏。
外部原生父窗口下的非空 Qt 屏幕关联也可能过期，错误的可用区域会被所有插件共享，
导致公共定位算法把正确的锚点坐标钳制到另一块屏幕。只重启能够暂时缓解，不能守住契约。

## Decision

taskbar 完成嵌入后，`PopupService::screenForNativeWindow()` 根据实际 HWND 的
`MonitorFromWindow` 结果，与 `QWindowsScreen::handle()` 匹配，取得对应 `QScreen`。
appbar 使用实际布局目标主屏。宿主继续向各插件提供原有逻辑坐标 `screenGeometry`，
不修改插件接口、钳制算法和每个插件的弹窗实现，也不混用 Win32 物理矩形与 QML 坐标。

宿主在最终布局、原生窗口移动、屏幕/DPI 消息和工作区变化后刷新边界。原生消息后的
刷新排到下一轮事件，避免在 Qt 完成屏幕及缩放处理之前读取中间状态；区域未变化时不
重复更新 QML 上下文。无法取得原生监视器时保留 Qt 关联和主屏回退。

Qt 原生屏幕接口与项目锁定的 Qt 6.9.3 一起使用，升级 Qt 时需要重编并验证该边界。

## Alternatives considered

- **始终使用主屏**：符合目前状态栏主屏布局，修改最小；但 taskbar 的原生父窗口与
  主屏关联会在系统显示配置变化时更新，直接识别实际 HWND 能避免再次依赖隐含假设。
- **每个插件自行修正屏幕或坐标**：可以局部规避问题；但错误数据源由宿主统一注入，
  会重复产生不一致的定位实现，因此修正共享来源。

## Verification

原生探针确认修复前状态栏 HWND 位于主屏任务栏，三个既有弹窗 HWND 坐标落在左侧副屏。
针对实际多屏环境增加原生监视器匹配、外部原生窗口包装、从另一屏复用弹窗的回归。
任务栏测试继续运行多组缩放环境；单屏环境只跳过必须有第二屏的用例。

`pixi run build` 通过；完整 CTest 44 项通过，包含新增的 Windows 原生多屏回归和
既有 1、1.25、1.5、2 缩放任务栏测试。笔记校验通过。

重启真实便携宿主，依次打开玄枢菜单、系统信息和 Token Usage。三者的 Qt 屏幕均为
任务栏所在主屏；原生窗口矩形均在主屏可用区域内，DPI 均与任务栏一致。验收后恢复
临时探针并再次重启，插件文件与源码哈希一致，用户配置内容哈希保持不变。

## Consequences

所有使用作用域屏幕区域的标准弹窗和独立提示共同受益。代价是公共定位服务增加对 Qt
Gui 与 Win32 原生屏幕句柄的依赖。测试不会调整用户的显示器排列、系统缩放或工作区。
动态拔插显示器与用户实际改变系统 DPI 的人工交互仍需单独验收。
