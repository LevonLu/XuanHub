# Agent Note: 常驻内存与窗口内容生命周期

Status: implemented

## Problem

状态栏只显示少量信息，但设置窗口关闭后保留独立 QML 引擎，插件弹窗隐藏时仍保留完整详情内容。
Python worker 的 stdout 未被消费，第三方插件持续输出时存在宿主缓冲增长风险。

## Decision

设置窗口隐藏后延迟释放视图，独立保留负责异步依赖安装和更新回执的 ViewModel；重新打开时重建视图。
设置页首次访问时实例化，本次编辑期间保留非法输入和选中项；关闭窗口统一释放。
Token Usage 弹窗及其当前页面按需创建。保留共享 PluginPopup 的定位、互斥和关闭规则。
worker stdout 重定向到空设备，并验证无控制台进程的启动方式；保持 stderr 诊断和独立进程隔离。
优化前后在相同隔离便携配置下统计宿主和整个进程树的私有工作集及提交量。

## Historical audit

检索内存、驻留、生命周期、懒加载、stdout、设置窗口与隔离。命中
[紧凑弹窗](../../implemented/simplification/2026-11-02-agent-usage-compact-popup.md)和
[统一账户](../../implemented/feature/2026-11-02-token-usage-unified-accounts.md)，均部分重叠；它们的展示、
草稿、配置及凭据约束继续成立，本篇只改变资源存活时间。倒计时提示的非互斥语义无关，不修改；其余命中无关。

## Alternatives considered

长期保留视图可以使再次打开最快，但不符合常驻程序的资源目标。连同 ViewModel 一并销毁能释放更多内存，
但会中断更新任务或丢失依赖安装完成回执，因此先只释放窗口及其对象树。
合并 Python worker 可以减少固定进程开销，但扩大崩溃和 GIL 卡死的影响范围，因此保持隔离。
在 Loader.onLoaded 中写回决定 active 的访问标志会触发绑定循环，因此页面访问由 StackLayout
显式设置 active，不从加载完成信号反向驱动自身的创建条件。

## Testing

`pixi run build` 完成 Release 构建，完整 CTest 44/44 通过；另行运行真实组件 QML 回归，32/32 通过。
新增回归覆盖弹窗首次打开前无详情、隐藏后销毁、重新打开后重建，以及工具页和账户页互相卸载。
真实 worker 输出 32 MiB stdout 后，宿主私有提交量增长小于 8 MiB，保留初始化噪声余量，避免复制实现作为断言。
插件 CLI 的 validate、doctor、两轮 Worker 生命周期与 QML run 通过；源码目录现有 Python 缓存仅产生静态告警。
正式运行目录重启后，实际检查外观、插件及 Token Usage 设置页，取消关闭正常；日志无 QML 错误。
日常运行 config.json 的 SHA256 与任务开始前一致，现有 README 修改保留。

内存对照通过 `scripts/benchmark_memory.py` 在隔离便携 taskbar 目录执行，保留 sysinfo、倒计时、Token Usage、
玄枢菜单与 pybridge，账户列表清空；没有保存用户设置或复制密钥。实际 worker 解释器为本机 CPython 3.13 x64。
每轮独立启动：bar 运行 15 秒，设置场景运行 30 秒，回放外观、插件、Token Usage、通用、外观、取消。
采样调用 GetProcessMemoryInfo 和 QueryWorkingSet，进程树只累加私有驻留，避免共享 DLL 页面重复计数。
每个阶段先取该轮的样本中位数，再取三轮中位数；提交量不等同于物理驻留。

单位 MiB，主表均为三轮中位数：

| 场景 | 宿主私有工作集，前 → 后 | 宿主私有提交量，前 → 后 | 进程树私有工作集，前 → 后 | 进程树私有提交量，前 → 后 |
|---|---:|---:|---:|---:|
| bar 空闲，10–15 秒 | 72.61 → 69.19 | 108.82 → 104.43 | 96.18 → 91.33 | 137.49 → 130.81 |
| 设置外观，5–9 秒 | 123.98 → 110.87 | 187.69 → 180.36 | 155.25 → 133.25 | 216.80 → 206.68 |
| Token Usage 设置，14–17 秒 | 137.46 → 129.95 | 208.20 → 203.05 | 161.21 → 152.30 | 237.00 → 229.45 |
| 设置关闭后，25–30 秒 | 143.78 → 105.19 | 208.45 → 160.64 | 167.57 → 127.37 | 237.21 → 187.23 |

设置关闭后宿主私有工作集降低约 26.8%，提交量降低约 22.9%；进程树分别降低约 24.0% 和 21.1%。
bar 稳态进程树从宿主、两个 Python 和两个 conhost，变为宿主与两个 Python；工作集中的共享页面不按进程数估算收益。

另一个对照加入隔离 hello 探针，通过现有 HostServices 连续打开设置十次，并用 QTest 回放三个导航页和取消，
38 秒结束前的 34–38 秒采样：宿主私有工作集 150.2 → 130.7，提交量 209.2 → 171.5。
两版均完成十次打开和十次取消，日志无 QML 错误；该探针多一个 Python 进程，不混入主表。

原始样本、逐轮日志、汇总和构建日志保留在本机忽略目录 `build/memory-optimization/`。

复现时先准备各自的独立运行目录，包含 portable 与 `.memory-benchmark` 两个标记，使用相同 config.json：

```powershell
python -B scripts/benchmark_memory.py <运行目录> --output <结果.json> --repeat 3
python -B scripts/benchmark_memory.py <运行目录> --output <十轮结果.json> --repeat 1 --reopen-only
```

## Consequences

主要收益来自使用设置后释放视图；冷启动改善较小，打开设置时的峰值仍然存在。
重建视图增加重开成本；设置编辑期间页面保持存活，保留非法输入、选中项和草稿。
Token Usage 弹窗关闭或切换页时释放详情，返回工具页显示总览；后端采集、账户与历史数据仍由原有模型保存。
ViewModel 跨视图存活，异步安装与更新的接收者没有被销毁；安装中关闭窗口的真实离线依赖流程未专项执行。

十轮开关后节省幅度缩小，QML、分配器和图形驱动仍保留部分缓存；这些短时数据不构成长时间无泄漏证明，
也不证明用户观察到的所有 35–300 MiB 波动都来自同一原因。真实 DPI、所有 Shell 层级和不同显卡仍需独立验收。
不使用强制工作集清空或周期性 GC 美化数字；当前结果来自对象释放与进程启动方式的改变。
