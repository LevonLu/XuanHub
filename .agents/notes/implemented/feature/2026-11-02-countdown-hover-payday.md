# Agent Note: 倒计时自定义悬浮提示与工作日发薪日期

Status: implemented

## Problem

状态栏的每日倒计时之外，用户需要鼠标悬停时查看自定义信息，包括每月 10 号遇休息日
提前到最近工作日的发薪日期。中国大陆周末可能补班，单纯排除周六日会算错实际日期。

## Decision

`plugins_py/countdown` 在既有配置版本 2 中增加可选的 `tooltipText`、`paydayDay`、
`paydayHolidays` 和 `paydayWorkdays`，旧配置默认不显示提示。设置页提供多行编辑器和
发薪日示例；模板只替换 `{payday}` 与 `{paydayDays}`，其余按用户纯文本显示。

Python 计算实际日期，QML 翻译固定状态。离线 `calendar_cn.json` 保存经官方通知核对的
2026 年放假与补班安排，公司覆盖项优先。无完整日历的年份显示待确认，不默认为普通
双休日。日历与按日计算结果有界缓存，刷新不发网络请求，配置更新先验证再替换。
发薪当天保留至本机午夜；已过实际日期跳到后续月份，短月取月末。
设置页只在用户激活模式选项时写入稳定值，文本编辑与草稿比较后再写回，避免初次注入时
用未就绪枚举覆盖配置、或因 `revision` 更新形成绑定循环。写草稿时核对插件 ID。

提示使用不接受焦点和输入的 `Qt.ToolTip` 顶层窗口，悬停 400ms 后显示，离开或点击 bar
关闭。它只复用宿主 `PopupService.calculate` 的定位，不注册互斥弹窗、不请求激活，
避免鼠标经过时关闭其他插件正在使用的界面。最终尺寸稳定后再次定位并显现。

宿主可用区域采用[原生屏幕选择](../bug-fix/2026-11-02-popup-native-monitor.md)，
与本篇部分重叠；提示的非交互与非互斥决定继续成立。

## Alternatives considered

- `QtQuick.Controls.ToolTip`：代码少且支持延迟；已有状态栏实现证明其默认弹层会被矮
  窗口限制并覆盖控件，因此采用独立提示窗口。
- 直接使用 `PluginPopup`：可复用全部生命周期，但 `openAnchored()` 会注册互斥并请求
  激活。非交互悬停提示需要保留其他交互弹窗，只复用定位计算。
- 使用第三方联网节假日服务或 Python 日历包：可扩大年份覆盖，但增加网络、更新源和
  便携包依赖。当前采用带来源的离线日历，承担每年更新成本，并公开未知年份的边界。

## Consequences

提示与原有倒计时独立，到点或目标时间格式错误时仍可查看发薪信息。公司日期覆盖允许
修正实际休息安排；对未知年份明确拒绝给出未经确认的日期。代价是日历需要逐年维护，
覆盖不全时无法确认下一次发薪日期；扩大覆盖时应更新数据及对应回归样例。

新增 Python 测试由现有 `xuanhub_pyworker_tests` 自动发现，包含真实 Worker 协议及
QML 悬停测试；Qt 缺失时只跳过 QML，不要求 Python 插件开发者编译宿主。
统一 CLI `test` 当前未传 `targetConfigVersion`，导致版本 2 插件被按版本 1 初始化；
回归直接使用同一 `WorkerHarness` 并传递真实版本，通用 CLI 保持此次范围之外。

## Testing

- 完整 Python 插件测试集 193 项通过；最后的设置页修改后，14 项专项测试再次通过，
  含两组 QML 用例：悬停窗口、设置页草稿注入及按钮编辑。中英文完整性、既有配置迁移、
  主视图 Smoke、依赖 Doctor 和 `pixi run verify-notes` 通过。
- 源插件已有 `__pycache__` 产生 Validator 警告；本次不把缓存作为分发内容。
- 复用本地现有编译宿主在独立便携目录重启，确认插件加载、设置页视觉、示例按钮和保存
  热更新，最终日志无 QML 绑定循环、类型赋值错误或 Worker 故障。验收目录使用本机
  Python，未修改用户原有配置。实际任务栏嵌入、多屏和不同 DPI 的提示视觉尚未验收。
