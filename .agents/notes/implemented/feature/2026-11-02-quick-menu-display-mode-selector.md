# Agent Note: 玄枢菜单显式选择显示模式

Status: implemented

## Problem

快速菜单用“任务栏模式”开关表达 `taskbar/appbar` 两种形态。关闭开关没有说明状态栏会移到哪里，用户无法在操作前理解结果。

## Decision

在菜单内以分段控件同时展示“任务栏模式”和“独立状态栏”两项互斥选择，通过明确的模式名称表达切换目标。视觉与 Token Usage 的页签一致：浅色轨道、圆角选中块、主题强调色文字；控件下方不附加说明文字，保持菜单紧凑。选中状态来自宿主 ViewModel；选择当前模式不发布命令，切换时先关闭菜单，再沿用 `taskbarMode` 命令的显式布尔参数。

“外观”同样使用“浅色 / 深色”分段控件，沿用 `lightMode` 显式参数，切换后保持菜单打开；重复选择当前主题不发布命令。两个控件只依赖菜单自身和宿主色板，不引入对 Token Usage 插件的运行时依赖。

## 历史决策检索

检索菜单、显示模式、taskbar 和定位，命中[菜单最终尺寸定位](../../implemented/bug-fix/2026-10-30-quick-menu-popup-placement.md)与[原生屏幕选择](../../implemented/bug-fix/2026-11-02-popup-native-monitor.md)。这两篇约束弹窗定位，本次只调整模式入口，继续使用 `PluginPopup`，不替代原决定；其余命中不涉及本问题。

## Alternatives considered

保留开关并添加副标题能保持菜单高度，但用户仍须把“关闭”理解为另一个模式，因此采用并列选项，直接呈现两个结果。下拉框节省高度，但需要展开后才能看到另一种形态，快速菜单只有两项选择，不采用该方案。

## Verification

- `pixi run build` 完成 Release 构建。完整 CTest 中其余目标通过；分段按钮由 Repeater 创建，回归最初按 QObject 树查找失败，改为按实际可视 Item 树定位后，受影响目标通过 `ctest --rerun-failed` 重跑。
- `PluginSlotHealthTest` 的顶部、底部和 taskbar 三组用例覆盖模式选中状态、点击当前模式不发命令，以及切换时发送 `taskbarMode=true/false` 并关闭弹窗；首次打开与动作列表增长仍验证屏幕包含性。
- 同组回归覆盖浅色和深色切换的参数、选中状态更新、重复点击不发命令，以及换色后菜单保持打开。
- 使用 Qt 6.9.3 的 Windows 窗口后端加载真实菜单，核对中英文、深浅主题与两种模式的截图。

## Consequences

两个模式目标与深浅色选项在操作前即可见；分段形式减少垂直占用，代价是菜单保留 280 逻辑像素宽度以容纳中英文选项。菜单保持原有限高和滚动，最终内容尺寸仍交给宿主重新定位。

本次沿用宿主原有命令、配置与窗口切换行为。测试窗口和截图不代表真实 Shell 嵌入及全部 DPI 的人工验收；运行中的宿主须重启以刷新 QML 缓存。
