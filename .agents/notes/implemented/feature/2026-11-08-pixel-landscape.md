# Agent Note: 常驻像素小风景与可选内容宽度输入

Status: implemented

## Problem

状态栏需要离线、低干扰且可以选择主题的像素风景。固定构图直接裁剪会在槽位收缩时丢失地标；持续重画完整大图会增加常驻开销。

## Decision

自动模式的固定时段与无外部位置来源边界由[真实太阳光照](2026-11-09-pixel-landscape-solar.md)部分取代；本篇的场景构图、共享时钟、按需弹窗、画框和槽位宽度决定继续成立。

原生 SDK V2 插件 pixel_landscape 使用 C++ 管理配置与三十秒校时，QML 共享动画时钟，以有限调色板在小尺寸静态、动态画布中绘制四时段、三天气。栏上默认自然内容宽度 320，弹窗内容按需创建、关闭释放，沿用 PluginPopup。画面占满弹窗，窗口使用不透明主题背景，无需透明合成表面。

可选配置 scene 提供 cabin、lighthouse、street、campsite、railway、island 六种场景，缺省 cabin 保持已有配置的画面，configVersion 仍为 1。设置使用现有 schema，不自动更改天气或时段。ViewModel 先校验整个配置再应用，场景、画框、天气共享一次 configChanged 通知；切换不重建插件或弹窗，不清除暂停或动画时间。

五个新增场景各用独立绘图模块管理等比地标和远近层次，SceneArt 只提取共同的天空、天气与像素基元。LandscapeScene 按 sceneType 选择当前模块，同一对 Canvas 重新绘制，几何仅在场景或尺寸变化时生成。灯光、火焰、风车与列车全部由既有动画时间推导，不增加场景定时器或累计对象；列车每 90 秒经过约 12 秒，属于常规场景动画，rareEventsEnabled 继续只控制流星。

PluginSlot 只对声明 hostContentWidth 的插件注入扣除内边距后的实际宽度，并改用其 implicitWidth 统计自然尺寸，避免反馈循环；旧插件维持原宽度规则。接口仅增加可选 QML 属性。

设置模型对从未配置过的新发现插件使用 Manifest 的合法 layout.region 作为初始位置，确保风景首次启用时位于中间；已有条目的用户位置保持不变，缺省或非法声明仍回退 right。

宽度不足 32 时使用当前场景的简化地标并停止栏上动态细节。高地标的缩放同时受宽度和上下空间约束，避免灯塔塔尖或风车叶片被低矮栏裁掉。画布始终使用有界粒子和固定种子；暂停、隐藏和时钟跳变不补播历史帧。正常时段变化的二十秒渐变复用同一时钟。

栏上与欣赏弹窗共用可选配置 frameStyle，提供 none、thin、wood、mat、metal 五种样式，缺省为辨识度更高的 wood；未含该键的既有配置直接采用新缺省，configVersion 保持 1。该键沿用 schema 草稿、保存与热更新路径，非法枚举或类型拒绝整次配置应用。画框是独立静态 QML 几何，框厚受实际宽高限制；弹窗画框仅作用于上方像素画区域，画面向内留出框厚；底部工具栏和定位信息保持普通面板。切换样式不重建插件、不清除暂停状态、不改变自然宽度或弹窗外部尺寸。

窄屏工具栏的行数先按屏幕可用宽高计算，不能依赖最终窗口 width，否则 width → sceneWidth → toolbarHeight → width 形成绑定循环。真实设置窗口验证还暴露 schema 枚举在 field 注入后被 model 重置的问题：枚举的 init 顺延到绑定稳定后，避免保存的 dusk 被显示成 auto；实际编辑器的动态注入回归覆盖此时序。

## Historical audit

已检索像素、宽度、弹窗和内存相关活跃笔记。没有相同主题；[视图生命周期](../../implemented/architecture/2026-11-02-runtime-memory-lifetime.md)和[弹窗定位](../../implemented/bug-fix/2026-10-30-quick-menu-popup-placement.md)部分重叠，继续遵守其按需创建和共享定位约束，不替代原决定。

## Alternatives considered

Python 骨架适合数据采集，但本插件无外部数据源，独立 worker 只增加常驻成本。预烘焙整幅精灵图能减少绘制逻辑，但宽度、天气和昼夜组合会扩大素材维护量；小尺寸分层画布保持构图和调色可复现。直接使用槽位裁剪不需要接口增量，但不能保证窄宽度保留视觉中心。

单一主题细框配置最少，但在复杂栏背景中不够明显，因此保留为可选项并增加木框、卡纸和金属材质。画框使用静态矩形和少量固定装饰，避免引入图片资源、阴影纹理或额外动画；更厚的样式会减少有效风景面积，低矮与窄槽位自动缩薄，极窄场景取消装饰。

将新增场景全部塞进原有小屋函数可以少建几个文件，但会混合互不相干的地形、坐标与动画分支；分场景模块保留可独立调整的构图，仅共享真正一致的像素基元和天气。也不为每个场景常驻一个隐藏 Canvas，避免未选场景消耗纹理和更新预算。

## Testing

专用测试覆盖时段边界、跨午夜和时钟跳变，配置拒绝，暂停与隐藏恢复，零宽和固定宽度，自然宽度稳定，旧插件行为，弹窗释放与重开暂停状态，流星调度，英文窄屏布局，语言包键一致。六场景共七十二种时段天气组合及各六档宽度实际渲染，另检查 schema 缺省和选项、非法 scene 拒绝、打开弹窗时热切换不重建内容、暂停和天气画框保持，以及中英文场景名称。

Release、完整 CTest 和插件 CLI 的验证结果、实际检查图、独立探针与完整宿主的 CPU/内存口径集中记录在[验证记录](../../../../docs/pixel-landscape-validation.md)。Qt 四档缩放回归与实际系统 DPI 切换、跨屏和休眠验收明确区分，未执行项不视作通过。

测试目标在构建后通过 Qt 导入目标显式部署对应配置的离屏平台插件。主程序的 windeployqt 默认只带 Windows 平台，独立提交副本的全新构建不能依赖开发运行目录曾手工留下的 qoffscreen.dll。

## Consequences

原生承载避免额外解释器进程，确定性几何便于组合和适配宽度，但 Canvas 仍有图像上传和 JavaScript 绘制成本；以后增加更复杂场景必须重测。内存预算同时受 Qt 窗口、字体和图形驱动影响，独立空窗口对照不能代替同配置完整宿主的启用/禁用对照；超过预算须保留实测差距，不能把缓存释放与常驻提交量混为一谈。

当前工作区的其他功能改动保留，默认配置不自动启用新插件。原生 DLL 替换须退出宿主，QML 更新也须重启验证。发布包、tag 与远端发布另行安排。
