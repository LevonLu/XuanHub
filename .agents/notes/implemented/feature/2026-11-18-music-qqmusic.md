# Agent Note: QQ 音乐同步歌词与定向播放控制

Status: implemented

## Problem

玄枢状态栏需要复用播放器已有的歌词和进度。浏览器等程序也可能正在播放媒体，所以播放控制需要绑定歌词所属的播放器。会话消失时，固定宽度和主题间距也需要随槽位一起收起。

## Decision

音乐插件用 C++/WinRT 枚举 SMTC 会话并匹配 QQ 音乐的应用 ID。命令送给当前绑定的会话，界面以读回的播放状态和能力为准。后续播放器只需在会话发现和歌词来源处接入，歌词时间轴与界面复用。后台线程处理 Windows 调用和本地文件，在 GUI 线程按单调时钟安排换行。歌词结果关联曲目版本，失去该会话或切歌后立即清空旧内容。

QQ 音乐适配先按曲名与歌手识别本地缓存，再用专辑和时长区分版本。QRC 解码有输入和解压大小上限，失败时尝试同曲 LRC。缓存稍后出现时自动补入，歌词缺失时呈现歌名。双行歌词默认突出当前句，也可通过 `doubleLineFont` 设为同样大小。已有配置采用新默认，两种样式保持 32 逻辑像素的双行高度门槛。弹窗使用共享 PluginPopup。

宿主读取 ViewModel 可选的 `barItemVisible` 布尔属性和通知信号。设为 false 时从宽度分配、三栏和溢出列表一起移除，保留运行中的 ViewModel。设置页继续显示该插件的运行状态。

## Historical audit

检索了 QQ 音乐、歌词、可见性和宽度预算。现有[视图生命周期](../architecture/2026-11-02-runtime-memory-lifetime.md)和[弹窗定位](../bug-fix/2026-10-30-quick-menu-popup-placement.md)部分重叠，本次沿用按需创建弹窗内容和共享定位。朝暮的高度、宽度约定与本次共用宿主槽位接口，其场景与配置独立。

## Alternatives considered

全局媒体键实现简单，但浏览器与 QQ 音乐同时存在时会控制系统选中的会话。定向 SMTC 调用可直接遵循对应播放器的能力和结果。

只隐藏插件的 QML 内容会保留固定宽度、装饰或区域间距。由布局模型处理可见性可以同时收起这些占用，也能在尚未实例化 QML 时恢复槽位。

## Consequences

QQ 音乐会话和缓存格式变动可能影响歌词。定向控制仍独立取决于播放器上报的能力。宿主和插件间只增加可选的 Qt 属性契约，运行中的播放器检测可跨越槽位 QML 的销毁和重建。

## Testing

专用 QtTest 覆盖行时间轴、暂停、跳转、切歌时的旧结果、单／双行、低栏高、固定宽度和弹窗。宿主模型回归检查隐藏槽位的宽度与代理模型。真实缓存和真实播放器控制可通过专用测试的环境变量主动启用，常规 CTest 使用合成数据。

Release 隔离实例通过插件校验、QML Smoke 和全部 53 项 CTest。真实 QQ 音乐验证覆盖本地 QRC 解码和弹窗的暂停、恢复、上一曲与下一曲。用户在实际桌面确认，拖动 QQ 音乐进度后状态栏歌词重新对齐，浏览器同时播放时弹窗按钮仍只控制 QQ 音乐。
