# Agent Note: 设置插件列表支持组内拖拽排序

Status: implemented

## Problem

插件较多时，逐次点详情中的上下按钮不能直接表达目标位置；列表又按启用状态与区域分组，排序必须与可见分组一致。

## Decision

列表右侧提供拖动手柄、跟随名称、插入提示线及边缘自动滚动。拖动期间不改模型，释放时按源和目标的稳定 ID 一次性重排同组草稿。
同组限定为已启用且区域相同，跨组移动继续由位置和启用控件处理。未启用项不参与状态栏布局，且现有配置只保存已启用项，因此不提供不能持久化的拖动手柄。搜索期间停用拖拽并提示清空搜索，避免隐藏行的顺序含义不明。
保留上下按钮，二者共用分组与连续 order 规范化逻辑；不改变配置格式、草稿桥和应用保存事务。

## Historical audit

检索 proposed、implemented、rejected 中的排序、拖拽、SettingsPlugin 与设置列表。
[Fluent 设置界面](2026-11-03-fluent-settings.md)部分重叠，其控件样式、折叠和草稿生命周期约束继续有效；SysInfo 内部指标排序不在本次范围。
Token Usage 弹窗的搜索裁剪与本次宿主插件排序无关。

## Alternatives considered

拖动经过每行就修改模型可以即时挤开列表，但排序代理会改变源行和详情状态，取消时还需要完整回滚，因此只预览落点并在释放时提交。
跨分组拖动可以一起改位置或启用状态，但会让排序操作隐含启停插件；保留显式控件处理这些变化。
搜索时按命中目标插入能减少操作步骤，但未显示插件仍参与顺序，结果难以预判，因此清空搜索后才拖动。

## Testing

模型测试覆盖首尾移动、重复 order、无效目标、跨组拒绝、草稿字段保留与导出重载。
QML 离屏测试使用真实鼠标事件覆盖拖动预览与释放、取消、搜索禁用、滚动超过正常缓存范围和选中项稳定。
`pixi run build` 的 Release 构建完成，完整 CTest 46/46 通过，`pixi run verify-notes` 通过。
重启真实宿主后，将米家从第二项拖到右侧分组首位并拖回，选中项和详情保持对应，日志没有 QML 错误；最后取消草稿，运行配置的 SHA-256 与验证前一致。
真实窗口只验证草稿拖动；保存与重载由模型回归覆盖，不把这次桌面检查扩展为全部 DPI 或触屏验收。

## Consequences

移动到目标位置只需一次拖动，仍可用原有上下按钮微调。状态栏在应用/保存后更新，取消拖动无需还原模型。
长列表滚动时源行必须保留鼠标抓取；拖动期间增加列表缓存，结束后恢复。搜索与跨区域移动需要显式切换控件；未启用项没有可保存的顺序。
自动化无法覆盖所有触屏和真实多屏 DPI 情形。
