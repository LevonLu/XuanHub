# Agent Note: GitHub 宿主一键更新与退出后回滚

Status: implemented

## Problem

宿主目前没有软件更新入口，用户需要手动下载并替换便携包。用户确认首版就包含一键更新，先使用 GitHub，暂不支持 Gitee。运行中的原生模块与 Python 运行时锁住发行文件，便携目录还混有配置、密钥和第三方插件，直接覆盖目录会丢失用户数据。

## Decision

宿主从固定官方 GitHub 仓库的正式 Release 读取便携 ZIP 的名称、大小和 SHA-256。打包流程产生 `update-manifest.json`，记录版本与每个官方文件的大小、哈希；默认配置、便携标记和运行时数据不属于替换清单。旧版清单是判断本地修改及已删除官方文件的依据，无清单的手工开发目录拒绝一键更新。

下载与有界解压先完成校验，替换前再次检查旧文件和新增路径冲突。独立 `XuanHubUpdater.exe` 及其运行库复制到独立事务目录，握手后宿主正常退出。更新器持有目标目录互斥锁并等待父进程真正结束，按日志备份、替换和删除清单文件。新版报告版本、随机事务令牌和就绪状态后才确认成功；替换或启动失败时恢复旧文件并重启旧版。保留事务日志与备份用于诊断及中断恢复。

设置通用页和托盘提供检查入口；后台检查最多每天一次，可关闭，可忽略版本。检查和下载不会保存设置草稿，开始更新前明确提示退出与未保存更改。服务由宿主持有，不随设置视图关闭而取消。

## Historical audit

- [原生模块生命周期](../../implemented/bug-fix/2026-11-03-safe-native-module-lifetime.md)部分重叠：继续遵循进程退出后才替换 DLL 的边界，互链补充宿主更新事务。
- [常驻内存与窗口生命周期](../../implemented/architecture/2026-11-02-runtime-memory-lifetime.md)部分重叠：后台更新状态归宿主，保持设置视图可销毁。
- 插件包更新索引与安装事务只管理 `.xuanplugin`，不扩展为宿主安装器。

## Alternatives considered

- 直接从运行中的宿主覆盖文件可减少一个进程，但 Windows 模块锁及更新器自身依赖会造成半更新，因此使用复制到独立目录的进程。
- 整个目录替换可以简化发行文件清理，但便携目录混有用户数据及非官方插件，复制快照也可能落后于运行中的写入，因此采用清单驱动的文件事务。
- 双平台统一静态索引便于未来扩展，但用户将范围收窄到 GitHub，现阶段直接使用官方 Release 附件摘要，避免多维护一个外部索引。
- 纯 Win32 更新器可以只依赖系统运行库，但需要重复实现 JSON、哈希和文件事务；现有 Qt Core 类型能复用校验逻辑，连同 Core/CRT 复制到独立目录即可解除自锁，因此更新器只依赖 Core。

## Testing

`pixi run configure -B build/app-update` 和 Pixi 包装的独立目录 Release 编译通过；使用独立目录是为保留正在运行的默认构建。完整 `pixi run ctest --test-dir build/app-update -C Release --output-on-failure` 通过，新增用例还单独复跑通过。

- 正式版本比较、附件选择、错误及取消有回归；HTTPS 与官方来源约束不因重定向放宽。
- 真实 ZIP 验证路径穿越、链接、重复路径、大小写碰撞、错误哈希和版本；本地修改与受保护目录在退出前拒绝。
- 独立 Windows 进程覆盖握手、等待父进程、成功更新、文件占用回滚、新版启动失败及其子进程清理、离线日志恢复；配置、密钥和第三方文件保留。
- 真实 QML 卡片验证检查、确认、取消、忽略和错误重试；使用窗口级 `waitForPolish` 等待 Flow 及子布局，避免点击尚未完成布局的控件。
- 全新便携打包通过 staging 与 ZIP 安全门禁；从 ZIP 校验全部清单并解压后，实际宿主在 offscreen 环境完成主 QML 启动回执，访问 GitHub 后报告当前正式版本为 `0.4.4`，随后正常退出。Bundle Python 的第三方导入与隔离 hello Worker 生命周期通过。

## Consequences

用户可以在宿主内完成下载、替换与重启，同时保留用户数据并拒绝覆盖本地修改。代价是清单、包校验和备份增加磁盘占用及发布维护成本；升级仅覆盖已经带清单的正式便携版本。

启动回执证明宿主及主 QML 已就绪，不证明所有插件外部服务可用。保留的更新器支持无宿主的离线恢复；已损坏到不能装载 Qt 的目录不能依靠宿主入口自救。GitHub 访问、限流或缺失附件明确报告，不能显示为已是最新版。此次没有发布远端新版本，因此未执行实际跨远端版本升级；现网检查、真实宿主启动和隔离更新事务分别提供证据。物理 DPI、Explorer 和不同机器权限仍需手动验收。
