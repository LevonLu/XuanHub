# Agent Note: 主框架提供三种菜单图标选择

Status: implemented

## Problem

玄枢菜单的任务栏入口只有一种品牌图形，用户无法在主框架设置中选择已经确认的原版、
方框枢纽 A 和紧凑 H C。设置预览与实际菜单若各自绘制，后续比例修改容易出现不一致。

## Decision

在主框架外观页提供三种带预览的菜单图标，配置保存为 `bar.menuIcon`，稳定值为
`original/hub/compact`；缺失或非法值回退 `original`，兼容旧配置。
草稿沿用现有应用/保存事务和过期指纹，保存后由 watcher 加载；宿主通过已有保留状态
`app.quickMenu.state` 传递 `menuIcon`，插件原地更新图形，不重建实例。
宿主 QML 组件 `BrandIcon` 同时供设置预览和菜单使用；A、C 用原生几何图元，原版保留原蒙版。
本篇初始实现只改变状态栏中的菜单入口；用户追加的[托盘同步](2026-11-03-tray-icon-selection.md)
扩展这一范围。窗口和可执行文件图标继续使用原始资源。

## Historical audit

检索图标、icon、外观、appearance 和设置草稿。
[Fluent 设置界面](../../implemented/feature/2026-11-03-fluent-settings.md)部分重叠，沿用其原生控件、
色板与显式保存机制；[快捷菜单分段选择](../../implemented/feature/2026-11-02-quick-menu-display-mode-selector.md)
部分重叠，沿用现有 EventBus 状态通道，保留其菜单交互。
窗口生命周期笔记只涉及视图释放，本次不改变生命周期约束。没有被完全吸收的旧决定。

## Alternatives considered

将选择放进菜单插件私有配置，可以复用插件 schema；但用户要求在主框架设置中选择，
而且无论菜单当前是否启用，都应可设置默认入口外观，因此使用 bar 配置。

让设置页和插件分别保存绘图代码，可以避免新增共用 QML 类型；但预览与实际使用会产生
两份几何来源，因此由宿主提供一个共用组件。

给 PluginContextObject 新增专用属性，也能传递状态；现有快捷菜单已通过保留事件接收宿主状态，
因此复用该通道，避免为菜单专用设置扩展通用插件上下文。

## Verification

`pixi run build` 完成 Release 构建，完整 CTest 45/45 通过。
配置回归覆盖默认值、重载、保存、未知字段保留、非法值与删除字段回退；菜单回归覆盖保留状态
重放、原地切换和非法值回退，确认插件实例不变。QML 回归点击三个真实选项并检查宽窄布局。
设置预览与实际菜单使用同一 `BrandIcon`；浅色、深色预览已检查。
运行目录通过插件 CLI validate、run 与 doctor；真实宿主重启后菜单加载正常，任务栏嵌入成功，
没有新增 QML 加载错误，运行配置的 SHA-256 保持不变。
设置草稿接入现有应用/保存事务，并把新字段纳入过期指纹；本次没有在用户配置上执行保存。

## Consequences

用户可在主框架外观页比较并选择图标，保存后即时切换；共用图形组件保证预览与实际绘制一致。
代价是增加宿主 QML 类型及一个配置字段，需要同步 Smoke 与离屏测试的类型注册；旧配置默认原版。
原版保留位图蒙版的缩放特性；A、C 使用几何绘制。真实多 DPI 的任务栏观感仍需独立人工验收。
