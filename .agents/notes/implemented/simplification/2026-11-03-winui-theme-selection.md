# Agent Note: 内置主题精简为三套 WinUI 配色

Status: implemented

## Problem

内置 11 套主题混合编辑器色板、胶囊与玻璃外壳，设置窗口已采用 FluentWinUI3，整体层次和强调色缺少统一。

## Decision

内置仅保留 WinUI 蓝、青绿、鸢尾紫三套纯 JSON 色板，各自提供深浅模式，共用中性灰表面和状态色。
默认主题继续使用 `xuanhub-default` ID；同步硬编码兜底与界面防御色值。
移除其他内置主题；当前 Release 输出中同名旧目录移到构建目录下的备份，保留第三方主题发现与可信外壳扩展能力。
旧配置引用已移除主题时沿用现有默认回退，不自动改写用户配置。

## Historical audit

按主题、theme、ThemeRegistry、FluentWinUI 检索活跃笔记。
[设置界面采用 FluentWinUI3](../../implemented/feature/2026-11-03-fluent-settings.md)部分重叠：继续保留其控件样式、palette 传递和窗口生命周期，本篇只收窄内置主题集合。
其余命中涉及菜单、插件与项目流程，与主题集合无关。

## Alternatives considered

从原主题中保留 GitHub、Nord 等可减少配色改动，但各自表面偏色和状态色不同，不能统一 Fluent 设置窗口与插件弹窗。
只删除目录、保留原默认色板最省改动，但默认仍是编辑器风格，因此同步默认色板与兜底。
删除外壳扩展机制可进一步裁剪代码，但用户只要求精简配色方案，第三方扩展契约继续保留。

## Testing

通过 Pixi 精确构建 `xuanhub_theme_tests`，编译本次修改的 `ThemeRegistry.cpp` 和主题加载回归。
宿主正在运行，因此不重链其 EXE、不重启用户进程；其他 C++ 目标沿用已有 Release 构建。
运行完整 CTest：45/45 通过，主题测试确认三套色板均可加载、默认磁盘色板与内置兜底一致，可信外壳与路径越界回归仍在。

单独校验六组色板全部 11 字段，并核对主文字、次要文字、强调色及状态文字在背景、面板和悬停表面上的对比度，
以及强调背景上的文字对比度；最低值为 4.52:1。青绿浅色强调色使用 `#00756b`，避免在悬停表面低于 4.5:1。
三套主题与插件裸 QML 的防御色值已同步到当前 Release 运行目录。
使用 Qt 6.9.3 离屏渲染六组色板示意；该示意不是实际设置窗口截图，真实 Fluent 控件交互仍需运行中验收。
上述对比度只覆盖主题自有表面；透明任务栏会透出 Windows 底色，应用深色与系统浅色组合下仍有低对比度问题。
任务栏独立跟随系统明暗与颜色保底目前仅有讨论方案，本次主题精简没有实现该适配。

## Consequences

主题选项减少且深浅表面保持一致；第三方主题扫描和外壳扩展接口不变。
代价是原内置主题不再随仓库分发，旧主题 ID 会回退默认主题；用户需要在设置中重新选择。
运行目录的旧主题备份位于 `build/default/retired-themes-20261103/`，不进入分发包。
正在运行的进程保留组件缓存；主题 JSON 经重新加载配置刷新，裸 QML 防御色值及宿主内置兜底随下次构建、重启完整使用。
